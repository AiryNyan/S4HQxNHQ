# S4HQxNHQ란?

S4HQxNHQ는 심즈4에서 HQ 해상도 CC와 일반 해상도 아이템을 함께 쓸 수 있게해 주는 모드입니다.

## 1. 이걸 왜 쓰는 건가요?

심즈4에는 심 텍스처를 2048x4096 해상도로 불러오게 하는 HQ 모드라는 트윅이 있지만, 문제가 있습니다.

- 기본 게임의 아이템도 모두 2048x4096 해상도여야 합니다.
- CC도 제작자가 2048x4096 해상도로 만들어야 합니다.
- 이 조건이 맞지 않으면 텍스처가 검은색으로 깨져 보입니다.

그래서 지금까지는 기본 게임의 의상과 1024x2048 해상도로 제작된 CC를 전부 2048x4096으로 직접 변환하는 수밖에 없었습니다.

## 2. 해결 방법

S4HQxNHQ는 게임이 텍스처를 **읽는 순간에** 끼어듭니다.

불러오는 텍스처를 확인해서 일반 해상도(1024x2048)인 심 텍스처를 **메모리에서 가로·세로 2배로 늘린 결과**를 게임에 건넵니다. 

## 3. 기존 방법과 뭐가 다른가요?

- 텍스처를 불러올 때 실시간으로 처리하므로, nonHQ CC를  변환할 필요가 없습니다.
- 늘린 텍스처를 디스크에 저장하지 않으므로 디스크 용량을 더 차지하지 않습니다.
- 보간이나 AI 업스케일 없이 픽셀을 2x2로 그대로 복제하므로 화질은 원본과 같거나 약간 각져 보일 수 있습니다.

## 4. 작동 방식

### 4-1. d3d11.dll 프록시로 불러오기

- 게임은 `Game\Bin` 폴더에 있는 `d3d11.dll`을 Windows 시스템 폴더의 것보다 먼저 불러옵니다. S4HQxNHQ는 이 이름으로 배포됩니다.
- 시스템 `d3d11.dll`의 내보내기 함수 51개를 같은 이름으로 내보내고, 모두 진짜 시스템 DLL로 그대로 전달합니다. 그래픽(D3D11) 동작에는 관여하지 않습니다.
- 실행 파일 이름이 `TS4_x64.exe`일 때만 동작합니다.

### 4-2. 파일 읽기 가로채기

게임이 사용하는 다음 파일 함수의 주소를 S4HQxNHQ의 함수로 바꿉니다.

`ReadFile`, `SetFilePointerEx`, `SetFilePointer`, `GetFileSizeEx`, `GetFileSize`, `CreateFileW`, `CreateFileA`, `CloseHandle`

`.package` 파일과 `GraphicsRules.sgr`이 아닌 파일은 원래 함수로 그대로 넘깁니다.

### 4-3. 텍스처 늘리기

1. 게임이 `.package` 파일을 처음 읽을 때 패키지 헤더와 인덱스(리소스 목록)를 읽습니다.
2. 심 텍스처 리소스(RLE2, RLES, LRLE)마다 데이터 앞부분만 읽어 해상도를 확인합니다.
3. 늘려야 하는 텍스처는 게임이 보는 인덱스에서 크기와 위치를 메모리에서 바꿔 둡니다.
4. 게임이 실제로 그 텍스처를 읽을 때 원본 픽셀을 정확히 2x2로 복제해 건넵니다.

## 5. 설치 방법

- `d3d11.dll`을 심즈4 실행 파일(`TS4_x64.exe`)이 있는 폴더(`The Sims 4\Game\Bin`)에 넣으면 됩니다.
- 제거할 때는 `d3d11.dll`을 지우면 됩니다.

## 6. 파일 설명

게임을 실행하면 정상적으로 작동시 `Game\Bin` 폴더에 다음 파일이 생깁니다.

| 파일 | 내용 |
|---|---|
| `S4HQxNHQ.log` | 동작 기록. 정상이면 실행당 몇 줄입니다. (최대 1MB) |
| `S4HQxNHQ.cache` | 캐시 (최대 8MB) |

- 캐시에는 변환된 이미지가 아니라, 크기를 변환해야 하는 텍스처의 **정보**만 저장됩니다.
- 텍스처가 깨지거나 문제가 발생하면 캐시 파일을 지울 경우 해결되는 경우가 있습니다

## 7. 확인된 문제점

- 캐시가 없는 첫 로딩 때는 로딩 시간이 이전보다 늘어납니다.
- CC 제작자마다 제작 방식이 달라서, non-HQ CC를 변환하는 과정에서 텍스처가 깨질 수 있습니다.
